# 仓库工作规范

## 仓库范围

本仓库用于操作系统实验 2 的进程同步设计，以及实验 5 的存储管理设计。`exp2/doc/` 和 `exp5/doc/` 中的实验说明是需求依据；实现代码分别放入对应的 `src/` 目录。

当前尚无程序实现、依赖配置或自动化测试。不要假定存在运行命令、测试命令或指定的编程语言。新增实现时，同步补充实际依赖、运行步骤和验证方法。

## 隐私要求

- 禁止将个人姓名、学号、身份证号、手机号、个人邮箱、家庭地址、账号凭据或密钥加入公开仓库。
- 检查正文、页眉页脚、批注、修订记录、隐藏文本、文档属性、内部作者记录和嵌入对象；图片及截图也必须人工检查。
- 不要在示例、日志、截图或说明中写入真实个人信息、用户目录路径或设备用户名。示例使用虚构且明显为占位符的值。
- `.private/` 保存未脱敏原件，`.privacy-review/` 保存检查和渲染中间文件；两者仅供本地使用，禁止提交、强制添加或上传。
- `report/` 默认仅供本地使用。公开报告须先完成脱敏，然后仅为已审核的具体文件增加例外规则。
- 提交前检查暂存清单与差异，并对二进制文档重新提取正文、检查元数据。不要仅凭文件名或 `.gitignore` 判断内容安全。
- 使用仓库级匿名提交身份或经明确授权的公开身份。不要读取全局个人身份后写入公开提交记录。
- 若发现敏感信息已进入提交历史，先停止推送并处理历史；不得通过追加删除提交掩盖泄露。

## 修改与验证

- 保留实验说明的原始要求。仅有隐私清理需求时，不改写实验正文或悄悄修正原文中的算法示例。
- 修改 Word 文档后，确认可以正常打开，比较正文和页眉页脚，并检查每一页的显示效果；确认未重新产生个人元数据。
- 修改实验程序时，执行与变更相关的实际检查，记录结果；不要宣称未运行的测试已经通过。
- 保持同步机制和页面置换逻辑清晰。实验 2 的执行顺序应由并发控制决定；实验 5 应能比较不同算法和实存容量的结果。
- 提交只包含经过审查的文件。提交信息简洁描述实际变更，不含个人信息。
- 更新公开仓库前，检查将推送的全部提交，确认敏感原件、检查日志和生成文件均未进入历史。
