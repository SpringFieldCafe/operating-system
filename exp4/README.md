# 实验 4 进程调度

依据《操作系统-实验4.doc》，用 Python 模拟五个进程的动态优先数调度。程序和实验说明放在 `src/实验4_动态优先数进程调度.ipynb` 中，可以直接阅读并从上到下运行。

## 运行

需要 Python 3.10 或以上版本。Linux 下在本目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyter lab src/实验4_动态优先数进程调度.ipynb
```

在 JupyterLab 中选择 Python 3 内核，运行全部单元格。底部会出现五个进程的可编辑参数表，以及“初始化”“单步调度”“运行到结束”三个按钮。

1. 输入 P1 至 P5 的优先数和要求运行时间。优先数为整数，要求运行时间为正整数。
2. 点击“初始化”，按当前参数重新建立就绪链表。修改参数后也要再次初始化。
3. 点击“单步调度”，查看一次调度后的队列和全部 PCB；或点击“运行到结束”，保留逐步记录并完成模拟。
4. 展开记录中的“查看 PCB”，可以回看任意一步的完整 PCB 表。

## 实现约定

- PCB 包含进程名、下一 PCB 的 ID、剩余运行时间、优先数和状态。
- `id(pcb)` 表示模拟地址；`memory` 字典保存 ID 与 PCB 的对应关系，并在整个模拟期间保留全部 PCB。
- 队首和 `next` 字段都保存整数 ID，空指针为 `0`。队列遍历、摘除和插入均沿这些 ID 完成。
- 优先数越大越先执行。每运行一个模拟时间单位，优先数和剩余时间各减 1；尚未完成则按优先数重新插入，完成则置为 `E` 并退出队列。
- 原文没有规定同优先数的顺序：本实现把新插入的 PCB 放在已有同优先数 PCB 之后；初始同优先数按 P1 至 P5 的顺序排列。优先数可以减到负数。
- 只模拟调度，不创建实际操作系统进程，不实现现场保护和恢复。
- `perf_counter_ns()` 测量 Python 调度操作的实际耗时；模拟时间单位和该耗时分别显示。

ID 只在对象存活期间有效，重新初始化后的 ID 可以变化。Notebook 中保存了默认数据的运行结果；重新运行全部单元格后即可使用交互控件。按钮需要正在运行的 Python 内核。

## 验证

下面的检查只使用 Python 标准库，直接读取 Notebook 中的核心代码，检查链式指针、动态优先数、完成退出、同优先数顺序和随机数据的调度结果：

```bash
python src/verify_notebook.py
```

安装上述依赖后，还可以在独立内核中执行整个 Notebook，并测试三个按钮、参数修改和非法输入：

```bash
python src/verify_notebook.py --execute
```

默认测试数据的总运行时间为 14，完成后应有 14 条调度记录，五个 PCB 的剩余时间均为 0、状态均为 `E`，队首为 `0`。

实际执行结果见 [验证记录](VERIFICATION.md)。
