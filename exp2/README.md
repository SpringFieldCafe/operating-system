# 实验二：交互式进程同步

四个真实工作进程分别运行爸爸、妈妈、儿子、女儿，使用 Python 标准库
`multiprocessing.Pool`、`Condition` 和信号量协作。主进程负责 ManimGL 窗口与动画；
四个角色不会因为另一个角色等不到水果而失去运行机会。

## 启动

从仓库根目录执行：

```powershell
conda activate manim
cd exp2/src
python -m fruit_lab
```

窗口打开后，在同一个终端的 IPython 提示符中输入下列函数命令。
静默入口运行同一个场景，将依赖导入期间的提示记入本地错误日志，跳过 ManimGL 版本横幅；
仍可在命令后追加 ManimGL 参数。原有 `manimgl fruit_lab/scene.py FruitLabScene` 入口仍有效，
但其启动器自身会输出版本号及依赖提示。
终端保留输入提示符、历史建议和补全；启动帮助、命令反馈、主动查询结果与错误提示均不显示。
动画窗口中央偏上显示四行 TeX 公式 `empty`、`apple`、`orange`、`mutex` 及其当前值，
等号和数字分别对齐，原底部计数移至此处；保留等待气泡的原文字与原动画。
角色姓名、统计、顶部提示和详细同步讲解已移除；等待变怒及取放动画继续运行。
需要当前已有的 ManimGL 环境，实验已验证的上游源码版本固定在 `requirements.txt`。
`src/pi_family/requirements.txt` 另记录原有素材环境的发行版本号；源码版 API 可能随修订变化，
重新准备环境时应以实验目录的固定修订为准。
中文使用 Windows 的 `SimSun` 字体。水果、盘子继续使用已有绘图素材，
这是在教师允许直接绘图的前提下采用的形式。

数学符号来自真正的 LaTeX 排版，已预编译为 `src/fruit_lab/assets/tex/` 中的 SVG，
正常运行无需调用 TeX 编译器。重新生成这些素材时需要 `latex` 和 `dvisvgm`：

```powershell
python -m fruit_lab.math_assets
```

## 窗口与错误处理

交互窗口默认使用 1440×810 的 16:9 客户区。场景可见范围从 16×9 扩展为 18×10.125，
默认尺寸下仍为每场景单位 80 像素，角色、桌子和水果的尺寸、比例与场景坐标保持原样。
启动时会结合当前显示器工作区、
标题栏和边框选择可容纳的尺寸；屏幕较小时仅在启动时等比例缩小一次，随后锁定。
可通过标题栏在桌面上移动，保留最小化和关闭；禁用边框调整尺寸及最大化。
画面内部的拖拽平移、滚轮缩放和视角旋转均关闭，终端实验命令保持有效。

最小化期间四个工作进程、动作和同步确认继续推进，但停止 GPU 绘图；
恢复后显示当前状态，不重置实验或补播隐藏期间的画面。
最小化和恢复期间仍处理窗口事件，零宽或零高的临时绘图尺寸不会用于创建 GPU 纹理。

真正不可恢复的运行错误会结束实验并回收工作进程，详细堆栈保存在本地
`report/fruit_lab_error.log`，用户目录替换为占位符，该目录不提交。
参数错误等可恢复的命令问题同样静默记录到该日志，修正命令后可继续。

## 常用命令

| 命令 | 含义 |
| --- | --- |
| `father(3)` | 新增爸爸放三个苹果的请求 |
| `mother(2)` | 新增妈妈放两个橘子的请求 |
| `son(2)` | 新增儿子取两个橘子的请求 |
| `daughter(3)` | 新增女儿取三个苹果的请求 |
| `batch(father=3, mother=3, son=3, daughter=3)` | 同时提交多个角色的请求，便于观察竞争 |
| `cancel("father")` | 撤回爸爸尚未开始的请求，正在执行的一趟完成 |
| `cancel()` | 撤回所有角色尚未开始的请求 |
| `status()` | 保留命令入口，读取状态但不显示；需要检查时用 `save_log()` 保存 |
| `pause()` / `resume()` | 暂停或恢复业务和动作，暂停期间云朵变化、眨眼、扫视继续 |
| `speed(2)` | 动画二倍速；范围 0.25–4 |
| `step()` | 进入单步模式，放行一次取放及必要整理，释放操作权后停下 |
| `detail(True)` / `detail(False)` | 保留参数校验与设置，详细同步讲解不再显示 |
| `reset()` | 撤回待办，已开始动作完成后清空盘子、归位、清零统计，速度恢复 1 倍 |
| `demo("full")` | 收尾并重置后进入指定典型场景 |
| `events(12)` | 保留命令入口与参数校验，事件不显示但仍记录 |
| `save_log()` | 将当前状态与事件保存到本地 `report/fruit_lab_session.json` |
| `help_cmds()` | 保留命令入口，静默执行；命令说明见本文 |
| `exit()` | 退出 IPython，关闭场景并回收工作进程 |

次数是正整数，范围为 1–10000。重复输入表示追加。例如爸爸还有两次待办时
输入 `father(2)`，待办变为四次。每个角色同一时刻只执行自己的一趟，
接水果准备阶段已经属于正在执行的一趟，不会因 `cancel()` 半途丢弃水果。
单个角色完成统计在返程及完成反馈结束后增加；详细事件中的 `committed`
则表示实际取放接触已经发生。

`step()` 不指定哪个角色获胜。有符合条件的请求时由真实进程竞争；
没有资源时仍要补充对应角色请求。例如儿子等橘子时，可先输入 `mother(1)`。
单步在本次取放及必要的盘内整理完成、释放盘子之后停下，尚未完成的返程、展示、庆祝会在下一步或 `resume()` 时继续。
不要把返程尚未完成误认为请求已经丢失。

## 七个典型场景

每次 `demo()` 都先自动撤回尚未开始的请求，让已经开始的动作收尾，再从空盘开始。
重置收尾期间不接受新的角色请求。详细模式标志与速度设置保留。

| 场景 | 输入与后续操作 | 应观察到的现象 |
| --- | --- | --- |
| 缺少水果 | `demo("empty")`；观察后输入 `mother(1)` | 儿子在原位等橘子，随后被唤醒 |
| 盘满、缺少空位 | `demo("full")`；放满后输入 `daughter(3)` | 两个苹果占满盘子，爸爸第三次等待；女儿取出后爸爸继续 |
| 水果类型匹配 | `demo("types")`；观察后输入 `mother(1)` | 盘里有苹果，儿子依旧等橘子 |
| 阻塞与唤醒 | `demo("wakeup")` | 爸爸走近、放入前女儿等苹果；放入后女儿获得继续执行的机会 |
| 互斥访问 | `demo("mutex")` | 父母都有放果请求，但同一时刻仅一人拥有盘子操作权 |
| 四角色并发 | `demo("concurrent")` | 四人各三次，返程、行走、庆祝可重叠，最终盘子清空、每人完成三次 |
| 数量不配平 | `demo("unbalanced")`；观察后输入 `daughter(3)` | 爸爸完成三次、还等一次，盘内两个苹果；补足取果请求后全部完成 |

缺少资源是正常等待，不按“超过几秒未动作”判断死锁。本实验没有故意制造死锁的模式。
不同运行的竞争次序可以不同，核心检查的是资源约束、互斥和最终结果。

## 画面与动作

- 全部场景背景使用纯黑。妈妈、儿子从左侧操作，爸爸、女儿从右侧操作。
  角色水平位置保持原样；父母原位上移约 8 像素，子女下移约 12 像素，拉开上下两排间距。
  思考云随角色一起调整，取放时仍走到原有桌边接触位置。
- 缺果、缺空位或暂时没有盘子操作机会时，角色在原位等待。
- 等待原因以角色头顶的云形思考框显示，使用参考视频截图中原有云框的矢量化轮廓，
  主云约 8 个宽圆云瓣；小云也增加圆瓣并略微放大，整体长宽比保持原样；
  主云、小云各有四种基础轮廓：保留原稿，并各补充三份云瓣数量、分布不同的 SVG。
  两套轮廓分别随机打乱分配，四个角色的主云互不重复，小云也互不重复；
  只要还有云入场、显示或淡出，就保持这轮分配，整组退场后下次出现再洗牌。
  主云进一步收紧文字周围留白，文字和小云大小保持原样。
  主云下仅保留一朵小云，表示角色的内心想法。爸爸、女儿向右，妈妈、儿子向左，
  四组云都朝外侧；父母的主云额外上移约 4 像素，给中央与角色往返路径留出空间。
  小云放在眼睛与主云之间、略偏向主云，尺寸和原有形变保持不变。
  框体以 `DrawBorderThenFill` 描边后填充，中文以 `Write` 展开字形轮廓再填实，
  沿用原作者默认动画时长。参考轮廓的参差程度轻微收小；大小云都采用作者公开示例的正弦相位波，
  让鼓起的位置沿边缘传播；轮廓为纯正弦变化，参考中心和文字固定。
  四朵主云与四朵小云分别拥有独立的随机种子、起始相位、速度和随机传播方向，
  每朵云约 2.12–3.05 秒完成一轮形变。速度为本项目的对照调整，原片精确系数尚未确认。
  同一原因不重复入场，等待解除后淡出；云朵使用独立外观时钟，暂停取放或调整业务速度时仍持续变化，
  入场描边、书写与淡出也不会被业务暂停卡住。
- 等待满两秒后渐变愤怒；暂停业务期间不累加这段等待时间，眼睛仍继续活动。
- 父母在原位接住手边淡入的水果，持果走近、放果、收手，随后空手返回。
- 孩子空手走近、取果、持果返回原位，再开心或欢呼；短暂展示后水果淡出，恢复空手。
- 盘子允许任意两个水果，包含两个苹果或两个橘子。同类水果优先取手边那个，
  避免两个水果在取果前交叉换位。取走的水果离开补位区域后，剩余苹果向右、橘子向左补位；
  平移耗时 0.45 秒，补位完成后才释放盘子操作权。一苹果一橘子时保持左橘右苹。
  补位复用孩子原有的返程过程，以手持水果离开整条补位路径的实际间距为触发条件，
  不使用固定等待秒数；暂停、调速会同时作用于返程和补位。
  父母接住新水果后，若放果侧被占用，先将盘内旧水果让至另一侧，再走近放果。
  这些整理只改变显示位置，不生成/消耗水果，也不决定进程竞争的胜出者。
- 共用桌面的宽度为 1.06，比原来的 1.25 缩短约 15%；盘子只用长度 1.0 的横线表示，
  与下方桌面横线保持两层结构。桌腿、底座及水果尺寸保留，已有接触和行走预览沿用同一素材。

## 同步机制

池中恰好提交四个长期任务，各角色一个工作进程；后续命令进入对应角色的待办计数，
不会再把等待取果的小任务塞满整个池。工作进程入口定义在可导入模块中，兼容 Windows `spawn`。

`e` 表示空位许可，`a/o` 表示苹果/橘子许可，初值分别为 2、0、0；
二元信号量 `m` 表示盘子操作许可，初值为 1。共享条件变量保护检查、预留和待办计数，
资源不够或操作许可不可用时进行条件等待，不占用互斥许可干等资源。

只有资源和操作许可都具备时，角色才在条件锁内原子取得资源信号量与 `m`，
随后从原位出发。手接触水果时提交盘内变化并释放相应水果/空位许可，
收手后释放 `m`，此后返程可与下一个角色的出发重叠。
因此操作许可覆盖接近和取放阶段，不覆盖返程或庆祝，符合“原位等待操作机会”的交互约定。

中央四行公式显示**可申请的许可**：`empty=2`、`apple=0`、`orange=0`、`mutex=1`
为初值；已被出发角色预留的空位或水果不会重复计入，盘子有人操作时 `mutex=0`。
内部条件锁不单独显示，公式区域只使用 TeX 字形，没有中文说明。
字号沿用原数值的 27，公式区整体居中，覆盖约 Y=2.4–4.2 的上方空白区域。
首次启动时四个完整等式同时以作者原生 `Write` 动画描边、填充。
随后名称与等号完全固定，变化的旧数字先用 0.2 秒淡出，再以原生 `Write` 写入新数字；
连续变化合并到最新值，不积压旧数值，也不阻塞工作进程。
显示动画使用外观时钟，业务暂停或调速不改变其速度；重置和切换演示保留同一组前缀，
只更新数值。气泡的原文、字形书写、轮廓、相位波和入退场保持原样。
`save_log()` 保存盘内的实际内容，两者在搬运途中可能不同。
事件历史仍记录真实的 P/V 事件；进程选取由条件竞争和信号量控制，
动画的时长、随机眨眼或愤怒表情均不负责指定下一角色。

互斥许可、暂停单步、并发配平、重置后的前缀复用、等号对齐及人物/水果/气泡间距。

接触检查覆盖四角色与单线盘子的几何关系；最后两项验证已有表情、手势和行走能力。
